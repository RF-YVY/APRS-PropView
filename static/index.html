📖 APRS PropView — Help & User Guide

Overview

APRS PropView is a real-time APRS digipeater and Internet Gateway (IGate) application focused on visualizing VHF propagation conditions. It decodes APRS packets from RF (via a TNC) and APRS-IS, plots stations on a live map, draws signal paths, scores propagation quality, and adds weather radar plus configurable NWS alert overlays for faster storm awareness.

Watch the APRS PropView video guide

🗺️ Map

The central map shows your station (blue dot), RF stations (red border), APRS-IS stations (blue border), and optional weather overlays. Propagation lines animate from each RF station toward your position, color-coded by distance:

  • Red — < 31 mi (50 km)
  • Orange — 31–62 mi (50–100 km)
  • Green — 62–124 mi (100–200 km)
  • Purple — > 124 mi (200 km) — DX!

Small white dots along a path indicate digipeater hops.

🎛️ Map Controls

📍Center Map — Re-center on your station.
📏Toggle Lines — Show/hide propagation path lines.
🔴Toggle RF — Show/hide RF station markers.
Direct RFDirect RF Only — Show only RF stations heard directly, hiding digipeated RF and APRS-IS stations.
🔵Toggle APRS-IS — Show/hide Internet-heard stations.
🌙 / ☀️Theme — Toggle dark/light map tiles.
🏷️Callsign Labels — Show/hide callsign text above each station icon.
🔎Auto-Fit — Automatically zoom to fit all visible stations. Turns off when you manually pan or zoom; click again to re-enable.
⏱️Line Time Filter — Only show path lines from stations heard within the selected window (1h, 6h, 12h, 24h, or all time).
🏷️ Types ▾Type Filter — Check/uncheck station categories (Digipeater, Weather, House, Car, etc.) to control which types appear on the map.
SearchCallsign Search — Enter a callsign to jump to that station marker on the map.

Weather radar and NWS polygons are managed from Settings - Weather. All map toggle states, zoom level, position, and filter selections are saved automatically and persist across restarts.

Application update checks are managed from Settings - Web Interface. You can disable release checks entirely or choose how often the app rechecks GitHub while it stays running.

📻 RF Stations & 🌐 APRS-IS Tabs

Scrollable lists of stations heard on RF or via the APRS-IS network. Each entry shows the station's APRS icon, callsign, distance, heading, last heard time, and packet count. Use the filter dropdowns to narrow by time window, distance range, or station type.

📦 Packets Tab

A live feed of decoded APRS packets. Each entry shows the source (RF port or IS), timestamp, raw packet contents, and decoded fields. Use the source filter dropdown or the Clear button to manage the list.

💬 Messages Tab

Send and receive APRS messages. Type a destination callsign and message text (max 67 characters), then click Send. Incoming messages appear with ack/rej status indicators. Click any received message's callsign to auto-fill the To field for a quick reply.

Use the sort selector to view newest-to-oldest or oldest-to-newest. The mobile UI includes the same ordering behavior and a manual refresh button.

Message notification channels (Discord, Email, SMS) are configured separately from band-opening alert channels in Settings → Alerts.

📊 Propagation Tab

Real-time propagation scoring with stat cards: RF stations (1h/6h/24h), max distance, average distance, and APRS-IS count. Includes a distance distribution histogram and a 24-hour propagation history chart showing station count and max distance over time.

📊 Analytics Tab

Advanced analysis subtabs:

  • Longest Paths — Leaderboard of the greatest distances reached.
  • Heatmap — Time-of-day vs. distance heatmap showing when propagation peaks.
  • Station Reliability — Which stations are heard most consistently.
  • Best Times — Hourly chart showing the best time of day for propagation.
  • Alerts — History of band-opening alerts triggered by the system.

⚙️ Settings

All settings are saved to config.toml next to the executable. Most UI, weather, alert, and analytics changes apply live; transport-layer changes such as TNC connection settings may still require a restart.

The top of Settings includes a first-run checklist, settings import/export buttons for safe experimentation, and a last-transmitted history panel for station, WXnow, status, MHeard, and weather-alert beacons.

Station

Your callsign, SSID, latitude/longitude (or use the 📌 map picker), APRS symbol, status comment, beacon interval (minutes), and beacon path (e.g. WIDE1-1). Use Preview Station Beacon to inspect the exact packet text before using Transmit Station Now.

GPS Ingestion

GPS ingestion lets APRS PropView use a live position instead of only the saved station latitude/longitude. Turn on GPS Ingestion, choose a source, then choose whether GPS should only move your map marker or also update the station latitude/longitude fields.

LOCK prevents active GPS from changing the saved station latitude/longitude. Leave it enabled when you want GPS to move the map marker during mobile use without changing your configured home/base station position.

  • This browser/device - Uses browser geolocation from the current desktop or mobile browser. Use this when running the app from a phone, tablet, laptop, or remote browser that can provide location permission.
  • Own APRS position packets - Uses your own heard APRS position packets as the live GPS source. Use this when a radio/TNC, tracker, or Mobilink-style setup is already transmitting your current position into APRS PropView.
  • NMEA serial GPS - Reads NMEA GPS sentences from a local serial port such as a USB GPS puck, GPS-enabled TNC, or serial feed from another device.
  • NMEA TCP stream - Connects to a TCP host/port that provides NMEA sentences. Use this with network GPS bridges, companion software, or devices that expose GPS over TCP.
  • NMEA UDP listener - Listens for NMEA sentences sent to the configured UDP bind address and port. Use this when another app or device broadcasts GPS updates over the LAN.
  • Any source - Accepts the latest valid GPS fix from any supported source. This is useful for testing, mixed mobile/base setups, or fallback workflows, but selecting a specific source gives clearer status messages when a device is missing.

Move my map marker from GPS controls whether the live GPS fix moves your station marker on the map. Update station latitude/longitude also writes the live coordinates into Settings when unlocked; save the configuration if you want those coordinates kept after restart.

Digipeater

Enable/disable the digipeater. Configure which aliases to respond to (WIDE1-1, WIDE2-1) and the de-duplication window to prevent re-digipeating the same packet.

IGate

Enable/disable Internet gateway. Choose RF→IS (gate heard RF packets to APRS-IS), IS→RF (gate APRS-IS packets to local RF), or both.

APRS-IS

Server/port (default: rotate.aprs2.net:14580), your APRS-IS passcode, fixed or moving range filter mode, range in miles, and any extra filter expressions. Fixed stations generate filters like r/35/-79/80; moving/mobile clients can use m/80. Extra javAPRS filters such as b/CALL, t/poimqstunw, or -p/CW are appended as entered.

RF Ports

Add one or more named serial or TCP ports. Serial ports can use binary KISS frames or receive-only TNC2 monitor text for older radios. Kenwood TH-D7/TH-D7E users commonly need PACKET mode, 9600 bps PC speed, and Xon/Xoff flow control. Legacy single serial/TCP controls have been replaced by this multi-port list, but old saved config is imported automatically.

Status, Dynamic, MHeard, and Weather Alert Beacons

Status/DX can transmit a compact propagation summary, rotate preset dynamic messages in sequence or randomly, send a direct-heard RF MHeard list, or beacon severe weather alert text when active. Use Preview Next Beacon and the weather-alert preview before one-shot transmit or enabling periodic beaconing.

WXnow Transmit

WXnow can send APRS weather packets from a local WXnow.txt, with optional position included in the packet. When positionless weather is selected, PropView can seed a matching weather-symbol position packet and then transmit the positionless WX report. Use Preview WXnow before Transmit Now.

Web Interface

Host/Port — Bind address and port for the web UI (default 127.0.0.1:14501). Use 0.0.0.0 to allow network access.

Font — Choose a display font for the entire UI.

UI Theme — Switch the application interface between dark and light mode independently from the map tile theme.

Units — Choose Imperial or Metric for distance, map weather temperature, APRS WX station temperature, wind, and precipitation displays.

Map Tiles — Use the default online OpenStreetMap tiles or point PropView at a custom XYZ tile URL such as a local MBTiles/XYZ server. Custom URLs must include {z}, {x}, and {y}.

Ghost After (min) — Stations not heard within this time will fade (pulsing dashed border, reduced opacity). Set to 0 to disable ghosting.

Expire After (min) — Stations not heard within this time are completely removed from the map. Set to 0 to never auto-expire. Ghost time should be shorter than expiry time so stations fade before disappearing.

Update Checks - Enable or disable automatic GitHub release checks and set how often the app should poll for a newer published version during long-running uptime.

Tracking

Max Station Age — How long (minutes) to keep a station in the database before cleanup removes it. Cleanup Interval — How often (minutes) to run the cleanup process.

Alerts — Band Opening Channels

Trigger an alert when propagation exceeds thresholds (min RF stations + min distance). Cooldown prevents repeated alerts. Quiet hours suppress alerts during specified times. Channels: Discord webhook, Email (SMTP), and SMS via email gateway.

Use Send Test Alert to send a preformatted test message to selected Discord, Email, and SMS destinations without waiting for a real alert trigger.

Alerts — Message Notification Channels

Separate channel toggles for forwarding incoming APRS messages to Discord, Email, or SMS — independent from band-opening channels.

Weather

Enable weather with a US zip code or ICAO airport code. Current conditions use Open-Meteo. Alert sources can be automatic, Weatherbit with a user API key, or disabled. Auto uses NWS for US stations and Open-Meteo risk indicators outside the US.

When using WXnow as the current conditions source, the Open-Meteo condition fallback can still provide general condition text and icon while temperature, wind, humidity, and pressure come from your local station.

Map Overlays - Turn radar and alert polygons on or off, adjust radar opacity, enable radar animation, and choose which alert categories should be drawn on the map. Polygons display only when the selected alert source returns geometry.

Alert Polling - NWS county/zone UGC scope is available for US locations. Other alert sources use point-based or provider-defined coverage.

Adaptive Severe Weather Polling - When one of your configured trigger events, such as Tornado Watch or Severe Thunderstorm Watch, becomes active, alert polling automatically speeds up to the elevated interval so newly issued warnings are detected more quickly. After the trigger clears, polling stays elevated through the configured cooldown before returning to normal.

MQTT Integration

MQTT is for sending APRS PropView events and propagation status to other systems. It is not needed for normal APRS, digipeater, IGate, mapping, or messaging operation; enable it when you have an MQTT broker such as Mosquitto, Home Assistant, Node-RED, EMQX, or another dashboard/automation system that should receive PropView data.

Common use cases include showing current propagation level on a wall dashboard, triggering Home Assistant or Node-RED automations when a band opening alert fires, logging propagation metrics into another time-series system, or bridging PropView status to a shack display without scraping the web UI.

Configure the broker host, port, topic prefix, and optional username/password. The default topic prefix is aprs/propview. APRS PropView publishes retained propagation metrics on aprs/propview/propagation, retained summary values on aprs/propview/score and aprs/propview/level, and alert events on aprs/propview/alert.

📱 Mobile View

Access /mobile from a phone browser (e.g. via Tailscale) for a touch-optimized interface with Messages, Map, Stations, Propagation, and About tabs. The mobile Share GPS button can feed the phone's browser location into GPS ingestion when the source is set to This browser/device or Any source.

⌨️ Tips

  • Units can be changed in Settings → Web Interface. The map legend distance toggle also switches the same Imperial/Metric preference.
  • All map UI preferences (toggles, filters, zoom, position, map theme) are saved automatically to your browser and restored on next launch.
  • The desktop UI light/dark theme is saved separately from the map light/dark theme.
  • Ghost + Expire work together: set Ghost to 60 min and Expire to 180 min, for example, so stations fade at 1 hour and vanish at 3 hours.
  • Auto-Fit zoom (🔎) will keep all visible stations in view and zoom back in as stations expire. It turns off when you manually pan or zoom — click the button again to re-enable.
  • The propagation score is calculated from RF station count, maximum distance, and average distance within the last hour.
  • If you want faster warning pickup for a surrounding county, switch alert scope from Station point to County/Zone UGC and enable elevated polling triggers in Settings → Weather.
  • For mobile operation, keep station latitude/longitude locked if you only want GPS to move your map marker. Unlock it only when you intentionally want the live GPS fix to update your saved station coordinates.
  • Use settings export before changing host, port, APRS-IS, or RF port settings so you can quickly restore a known-good configuration.

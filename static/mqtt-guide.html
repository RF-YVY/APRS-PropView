APRS PropView MQTT Setup Guide

MQTT support publishes PropView propagation status and alert events to an MQTT broker. PropView is a publisher, not a broker, so Home Assistant, Node-RED, and dashboards need a broker such as Mosquitto between them and PropView.

How The Pieces Fit

APRS PropView connects to an MQTT broker and publishes topics. Other systems subscribe to those topics.

APRS PropView  --->  MQTT broker  --->  Home Assistant / Node-RED / dashboard

If Home Assistant is your goal, the common path is to install the Mosquitto broker add-on, then point PropView at the Home Assistant host or IP on port 1883.

PropView Settings

In PropView Settings, open MQTT Integration and set:

  • MQTT Enabled: checked
  • Broker Host: the broker hostname or IP, for example homeassistant.local or 192.168.1.25
  • Port: usually 1883
  • Topic Prefix: usually aprs/propview
  • Username/Password: the broker credentials, if your broker requires them

Save settings and restart PropView. MQTT currently connects at startup, so broker changes need a restart.

Topics Published

With the default topic prefix aprs/propview, PropView publishes:

  • aprs/propview/propagation retained JSON with current propagation metrics
  • aprs/propview/score retained numeric regional propagation score
  • aprs/propview/level retained regional propagation level text
  • aprs/propview/alert JSON event payload when alerts fire

Example propagation payload:

{
  "my_score": 35.0,
  "my_level": "fair",
  "regional_score": 61.2,
  "regional_level": "good",
  "rf_stations_1h": 12,
  "max_distance_km": 420.5,
  "timestamp": 1779926400.0
}

Home Assistant With Mosquitto

  1. In Home Assistant, open Settings, Add-ons, Add-on Store.
  2. Install Mosquitto broker.
  3. Start the add-on and enable Start on boot.
  4. Create or choose a Home Assistant user for MQTT authentication.
  5. In PropView, set Broker Host to the Home Assistant host/IP, Port to 1883, and enter that username/password.
  6. Save PropView settings and restart PropView.

To confirm messages are arriving, install a tool such as MQTT Explorer and subscribe to aprs/propview/#, or use Home Assistant's MQTT integration diagnostics.

Manual Mosquitto Broker

On Debian or Raspberry Pi OS:

sudo apt update
sudo apt install mosquitto mosquitto-clients
sudo systemctl enable --now mosquitto

For a quick local test from the broker machine:

mosquitto_sub -h localhost -t 'aprs/propview/#' -v

If PropView runs on another machine, use the broker machine's LAN IP as the Broker Host.

Home Assistant Entities

If Home Assistant does not auto-discover these topics, add MQTT sensors in configuration.yaml:

mqtt:
  sensor:
    - name: "APRS PropView Score"
      state_topic: "aprs/propview/score"
    - name: "APRS PropView Level"
      state_topic: "aprs/propview/level"
    - name: "APRS PropView RF Stations 1h"
      state_topic: "aprs/propview/propagation"
      value_template: "{{ value_json.rf_stations_1h }}"
    - name: "APRS PropView Max Distance km"
      state_topic: "aprs/propview/propagation"
      value_template: "{{ value_json.max_distance_km }}"

Restart Home Assistant or reload MQTT entities after editing YAML.

Node-RED Setup

Node-RED also connects as an MQTT client. It subscribes to the same broker PropView publishes to, then routes the received messages into debug panels, dashboards, Home Assistant calls, or automations.

  1. Install Node-RED and confirm it can reach your MQTT broker. In Home Assistant, the Node-RED add-on can usually reach the Mosquitto add-on by using the Home Assistant host/IP and port 1883.
  2. Open the Node-RED editor, drag an mqtt in node onto the flow, and double-click it.
  3. Add a new broker connection. Set Server to the broker host/IP, Port to 1883, and enter the MQTT username/password if your broker requires them.
  4. Set Topic to aprs/propview/# to receive all PropView topics, or use one exact topic such as aprs/propview/propagation.
  5. Set Output to a parsed JSON object if your Node-RED version offers that option. Otherwise, wire the MQTT node into a json node.
  6. Wire the output to a debug node, deploy the flow, then watch the debug sidebar for PropView messages.

Useful starter flows:

  • mqtt in topic aprs/propview/propagation -> json -> debug to inspect the full propagation payload.
  • mqtt in topic aprs/propview/score -> dashboard gauge/chart node to display the regional score.
  • mqtt in topic aprs/propview/alert -> json -> notification, email, Home Assistant service call, or dashboard text node.

When using the wildcard topic aprs/propview/#, Node-RED puts the actual topic in msg.topic and the value in msg.payload. That makes it easy to use a switch node to route score, level, propagation, and alert messages down different paths.

// Function node example after aprs/propview/propagation
msg.payload = {
    score: msg.payload.regional_score,
    level: msg.payload.regional_level,
    rf_stations: msg.payload.rf_stations_1h,
    max_distance_km: msg.payload.max_distance_km
};
return msg;

Troubleshooting

  • If PropView logs MQTT: failed to connect, confirm broker host, port, username, password, and firewall rules.
  • If Home Assistant does not show updates, first verify topics with mosquitto_sub or MQTT Explorer.
  • If Node-RED does not show messages, attach a debug node directly to the MQTT node, subscribe to aprs/propview/#, and confirm the broker connection says connected.
  • If using Docker or a VM, remember that localhost means inside that container or VM. Use the broker's reachable LAN host/IP instead.
  • PropView publishes propagation periodically, so wait for the next propagation update after startup.
